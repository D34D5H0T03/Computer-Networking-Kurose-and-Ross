The Inspiration

This server was built from scratch as a practical implementation exercise, inspired by the classic networking textbook:

"Computer Networking: A Top-Down Approach"
— James F. Kurose & Keith W. Ross

By bypassing high-level web frameworks, this project allowed me to dive deep into the Transport and Application layers, manually handling TCP handshakes, parsing HTTP GET requests, and crafting raw HTTP responses.

How Sockets Work

At its core, this server relies on Sockets. A socket acts as an endpoint for a two-way communication link between programs running on a network.

  • Bind & Listen: The server binds to a specific IP and Port (like 8080) and listens for incoming traffic.
  • Accept: When your browser requests this page, a TCP handshake occurs, and the server accepts the connection.
  • Receive & Send: The server reads the raw bytes of the HTTP request, determines what file is needed, and sends the raw HTML file back over the wire.

Under the Hood: Server Mechanics

01. Socket Setup

The server establishes a TCP connection (SOCK_STREAM), binds to port 8080, and enables immediate port reuse. This allows the server to restart cleanly without waiting for the operating system to release the network port.

02. Request Parsing

Upon receiving a connection, it reads raw HTTP request bytes. It splits the headers from the body, extracts the requested path from the initial line, and determines the target filename (defaulting to index.html).

03. Response Crafting

The logic fetches the requested file from disk. If found, it builds an HTTP/1.1 200 OK response with headers like Content-Length. If the file is missing, it gracefully crafts a 404 Not Found response.

04. Connection Loop

Wrapped in a continuous loop, the server constantly awaits new traffic. It accepts the TCP handshake, receives the incoming data, sends the fully crafted HTTP response over the wire, and cleanly closes the client socket.
